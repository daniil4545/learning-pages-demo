# Учебная лекция в общей библиотеке

Проект: `~/Dev/self-projects/learning-pages-demo`.
Сайт: https://daniil4545.github.io/learning-pages-demo/
Перед работой прочитать `AGENTS.md` проекта.

## Назначение

Явный запрос лекции включает сбор материала, страницу и публикацию в библиотеке.
Формат HTML сам по себе не означает запрос лекции. Рабочие документы остаются в своём проекте.
Не публиковать другие материалы проекта вместе с лекцией.

## Подготовка

Содержание и оформление: `~/.claude/rules/theory.md`, `~/.claude/rules/html-pages.md`,
`~/.claude/templates/page.html`. Эти стандарты сохраняются; правила ниже задают место хранения.
Для лекции итоговый путь: `<проект библиотеки>/site/lectures/<тема>.html`.
Новая каноническая копия хранится в библиотеке; копия в `growth/lectures` не нужна.

Переиспользовать подходящий процесс `theory-notes`: источники, объяснение, примеры и проверка.
Статьи и обсуждения читать до цитирования. Для видео получать субтитры с таймкодами.
Не пересказывать видео по одному описанию. Сырые источники держать во временной локальной папке.
В лекции оставить ссылки, дату проверки и явные ограничения доказательств.
Рабочие кейсы обезличить; ключи, рабочие адреса и персональные данные исключить.

## Небольшие визуальные дополнения

Простые схемы не сопровождать пересказом «Как читать». Для сложной нотации пояснение допустимо.
В лекции использовать не больше одной короткой пошаговой анимации и одной небольшой модели.
Добавлять их только для объяснения механизма. Переиспользовать HTML/SVG и небольшой JavaScript.
Тяжёлые библиотеки, дополнительные сцены и видеорендеринг требуют отдельного запроса.
Условные параметры модели не выдавать за измерения. При отключённом JavaScript текст и схемы доступны.

## Аудио

Если аудио прямо запрошено, повторное согласие не требуется.
Иначе спросить: «Без аудио (по умолчанию) или добавить короткую аудиолекцию?».
Ожидание ответа на аудио не мешает подготовке HTML.

При согласии использовать существующий инструмент аудиокурсов в `~/Dev/self-projects/claudemy`.
Сценарий пробной аудиолекции принят владельцем; системный голос пока тестовый.
Подбор качественного голоса оставлен отдельной задачей.
Сначала проверить доступный локальный движок. Бесплатный запасной вариант на Mac: `say` и `ffmpeg`.
Не запускать автоматический выбор платного бэкенда по наличию ключа.
Сценарий для слуха хранить в `audio-scripts/<тема>.txt`, MP3 в `site/audio/<тема>.mp3`.
Сценарий объясняет тему без экрана и не читает таблицы или ссылки вслух.
Один эпизод длится не больше пяти минут. Более длинный материал разделить по темам.
Каждая часть имеет свою тему и завершённое объяснение; не разрезать рассказ посреди мысли.
Каталог пока прикрепляет один MP3. Поддержку нескольких частей добавить при первом таком выпуске.
При платном варианте отдельно согласовать стоимость и предел расходов.

## Добавление и публикация

1. Добавить страницу в `library.json`: `path`, `title`, `description`, `group`.
2. Поле `audio` добавить только после согласования и создания файла.
3. Выполнить `python3 library.py build`, `python3 library.py check` и тесты проекта.
4. Проверить страницу на ширине телефона и компьютера, схему и ссылки.
5. Для аудио проверить воспроизведение, паузу, перемотку и восстановление позиции.
6. Опубликовать через существующий workflow репозитория. Сохранить чужие изменения.
7. Проверить публичную страницу и дать владельцу прямую ссылку.

Общая навигация и браузерный плеер подключаются сборкой.
Отдельный переключатель скорости не добавлять. Пустой плеер не показывать.
Если публикация не удалась, сообщить причину. Локальный файл не выдавать за опубликованную лекцию.
